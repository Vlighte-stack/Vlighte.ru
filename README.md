# Vlighte.ru — контрольная точка 2.00.49

Снимок исходников рабочей версии от 31 октября 2026 года. Это исходники приложения, а не полный резервный образ хостинга.

## Изменения 2.00.46–2.00.49

- Исправлена неподдерживаемая в HOG 3.21.2 пара Beam Fx 5 / Index и сопоставление Offset.
- Для SHUTTER2/3 с неполной физической шкалой устранён конфликт диапазонов при сборке HOG. Полный диапазон команд в пульте ещё требует проверки; успешный импорт не означает совпадение единиц управления.
- Виртуальный DIM MA2 выбирает цветовые каналы своего модуля, исключая физический DIM3 и отдельные ячейки. Нативные связи RGB записываются через Cyan/Magenta/Yellow, как в экспорте HOG.
- Канал 3 IP1000 больше не константа: COLORRGB7 в модуле с виртуальным DIM передаётся как отдельный Sub Intensity 1 с исходным Default и включением в Virtual/Affected. Это обходит переключение цветовой модели I White/Intensity. При обратном преобразовании явно управляемый вспомогательный уровень возвращается в COLORRGB7 без комментариев восстановления.
- Виртуальные границы и явно заданный Default переносятся; неоднозначные составные шкалы и конфликты органов управления отклоняются явно.

[Результаты HOG и установки 2.00.49](docs/conversion-checks/IP1000/2.00.49/README.md): HOG PC 3.21.2, IP1000 42ch, Intensity 0/50/100%, канал 3 и главный RGB, независимость DIM3 и первой белой/RGB-ячеек, цветной CMY. Рабочий API сайта формирует HOG4/MA2/GDTF с теми же определениями, которые проверены в HOG. На 50% остаётся 127 вместо 128 у оригинальной MA2; округление Tilt и полный диапазон SHUTTER не исправлены этой серией. Физический прибор не подключался. MA2 используется как ранее измеренный оригинал; сгенерированный MA2 2.00.49 нативно в этой серии не импортировался. HOG 5.3.0 не проверялся.

**Полный прогон 2.00.49 обнаружил регрессии:** 108 ошибок на старых входах и по 81 на новых форматах/ZIP. Причины — 32-битный Default виртуального DIM Robe и совместимость старых HOG Virtual/Affected. [Подробный отчёт и полные результаты](docs/conversion-checks/IP1000/2.00.49/full-matrix/README.md). Версия сохранена как установленное состояние с известными проблемами, а не как полностью прошедшая проверку. Прежние отчёты 2.00.38/2.00.40/2.00.45 остаются историческими результатами и не заменяют нативную проверку этой версии.

## Изменения после контрольной точки 2.00.40

- Сохранены исходные физические шкалы режимных контроллеров и Default; виртуальный диммер переносит правильную область Affected. Неоднозначные области отклоняются.
- Исправлены назначения управления, RGB-гобо GOBO5 IP1000, Recording/Capture и FlowerEffect/Beam Split.
- Колёса передают названия, цвета и ссылки на изображения. Изображения сохраняются в ZIP с XML и в GDTF; обычный HOG/MA2 XML остаётся доступным.
- GDTF CIE и нативный HOG ColourMatcher XYZ переносятся без промежуточного округления до RGB. При проходе через MA2 точные XYZ хранятся в открытом colorimetry.json внутри ZIP; MA2 XML и сам пульт используют приближённый RGB.
- ZIP с colorimetry.json связан с соответствующим MA2 XML и слотами; несовпадающие профили, неверные индексы и нечисловые/бесконечные координаты отклоняются. При повторном открытии записи библиотеки точные данные сохраняются.

Результаты последней матрицы: [docs/conversion-checks/IP1000/2.00.45](docs/conversion-checks/IP1000/2.00.45/README.md). Те же IP1000 и десять внешних фикстур, 891 замкнутая цепочка из четырёх преобразований. Три отдельных прогона: прежние 33 файла, новые производные форматы и ZIP с ресурсами. В каждом: 0 ошибок, 228 совпадений и 663 структурных отличия по прежнему XML-анализу. В ZIP-прогоне все 79 прежних потерь точности цвета устранены: 37 017 проверенных точек, максимальная разница xyY около 7.1×10⁻¹⁵. Все XML-комментарии удалялись на границах.

Для точного повторного преобразования через MA2 нужно загружать весь ZIP с colorimetry.json. Отдельный MA2 XML ограничен RGB и не переносит исходный CIE. Это проверка данных нашего конвертера, а не точности Color Picker в пульте: в матрице 2.00.45 импорт в HOG PC/MA2 не тестировался; последующая выборочная проверка HOG 3.21.2 описана в отчёте 2.00.49. Физические приборы не тестировались. Структура XML и подписи пресетов могут изменяться. Старые комментарии восстановления для других функций сохранены, но в матрице не используются. 3D-модели не переносятся; сложные DMX Relations и неоднозначные зависимости требуют отдельного сопоставления.

## Возможности

- Преобразование HOG4 и MA2, сохранение исходных определений в XML для обратного преобразования.
- Выбор формата перед генерацией; сохранение на ПК предшествует фоновой отправке сформированных форматов на сервер. Отмена сохранения не отправляет запись в библиотеку.
- Имена MA-MA, MA-HOG, HOG-MA, HOG-HOG с суффиксом vlighte_ru; проверка повторов в библиотеке.
- Общедоступные просмотр и скачивание HOG/MA/GDTF отдельно; управление, IP и корзина доступны владельцу.
- Удаление, восстановление, окончательное удаление отдельной записи и очистка корзины.
- Флаги стран, единые шрифты, логотип и favicon; вход для редактирования расположен внизу библиотеки.

## Развёртывание на существующем хостинге

Python WSGI, стандартная библиотека Python; для блокировок записи используется Linux fcntl. ROOT определяется расположением app.py.

В каталоге аккаунта /var/www/u1815774/data:

- app.py → fixture-stage/app.py
- public/index.html → www/vlighte.ru/public/index.html и fixture-stage/public/index.html
- library/index.html → fixture-stage/library/index.html
- public/logo-pencil.webp → существующий каталог публичных изображений с сохранением адреса, указанного в HTML.

После замены обновить public/tmp/restart.txt в существующем публичном приложении. Существующие WSGI-обёртки, .htaccess, HTTPS и маршрутизацию сохранить.

Для чистой установки нужны отдельные настройки маршрутизации и закрытые зависимости: private/owner-auth.json, private/strobe.xml, private/known.json и профили, на которые ссылается known.json. Эти существующие файлы не включены в публичный репозиторий. Не заменять их пустыми файлами на рабочем сервере.

Рабочее хранилище пользователей, пароли, посетительские IP, saved-files, корзина, журналы и приватные настройки исключены. В документации опубликованы только выбранные пользователем результаты IP1000 и открытая внешняя тестовая выборка. Базу геолокации и флаги приложение получает отдельно с проверкой хешей; private/country-assets26.zip не входит в снимок.
